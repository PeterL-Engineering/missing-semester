### 2. Explore a cloned repo's history

Clone the repository for the class website.

- Explore the version history by visualizing it as a graph.
- Who was the last person to modify `README.md`? (Hint: use
  `git log` with an argument).
- What was the commit message associated with the last
  modification to the `collections:` line of `_config.yml`?
  (Hint: use `git blame` and `git show`).

**A:** Run the following commands

```bash
# Clone the repo
git clone https://github.com/missing-semester/missing-semester

# Find the last user to edit README.md
git log README.md

# Find which line has collections:
n=$(grep -n "collections:" _config.yml | cut -d ':' -f1)

# Find the corresponding commit hash
h=$(git blame -L $n,$n -s _config.yml | cut -d ' ' -f1)

# Display the commit message
git show -s $h
```

### 3. Removing a file from history

One common mistake when learning Git is to commit large files
that should not be managed by Git or adding sensitive
information. 
Try adding a file to a repository, 
making some commits and then deleting that file from history 
(not just the latest commit). 
You may want to look at this.

**A:** Run the following commands:

```bash
# Install git-filter-repo
sudo apt install git-filter-repo

# Clone fresh repo (no uncommitted changes)
git clone <repo_URL>

# Purge the file
git-filter-repo --invert-paths --path path/file.txt

# Re-add remote origin
git add remote origin <repo_URL>

# Push to origin
git push origin --force -all
```

### 4. `git stash`

Clone some repository from GitHub, 
and modify one of its existing files. 
What happens when you do `git stash`? 
What do you see when running `git log --all --oneline`? 
Run `git stash pop` to undo what you did with `git stash`. 
In what scenario might this be useful?

**A:** `git stash` stashes uncommitted changes so that the output of 
`git log ...` shows these changes under `refs/stash`.
The stash entry appears as a commit with message `WIP on master: <hash> <last commit msg>`.
`git stash pop` restores the changes that were previously stashed.

### 5. Git aliases

Like many command line tools, Git provides a configuration
file (or dotfile) called `~/.gitconfig`. 
Create an alias in `~/.gitconfig` so that when you run `git graph`, 
you get the output of `git log --all --graph --decorate --oneline`. 
You can do this by directly editing the `~/.gitconfig` file, 
or you can use the `git config` command to add the alias.
Information about git aliases can be found here.

**A:** Add the alias below to `.gitconfig`

```bash
[alias] 
  graph = log --all --graph --decorate --oneline
```

### 6. `.gitignore`
    You can define global ignore patterns in ~/.gitignore_global
   after running
   `git config --global core.excludesfile ~/.gitignore_global`.
   This sets the location of the global ignore file that Git will use,
   but you still need to manually create the file at that path.
   Set up your global gitignore file to ignore OS-specific or
   editor-specific temporary files,
   like `.DS_Store`.

### 8. Merge Conflicts 
Practice resolving merge conflicts by simulating a collaborative
scenario:
- a\. Create a new repository with `git init` and create a file
  called `recipe.txt` with a few lines (e.g., a simple recipe).
- b\. Commit it, then create two branches: `git branch salty`
  and `git branch sweet`.
- c\. In the salty branch, modify a line (e.g., change “1 cup
  sugar” to “1 cup salt”) and commit.
- d\. In the sweet branch, modify the same line differently
  (e.g., change “1 cup sugar” to “2 cups sugar”) and commit.
- e\. Now switch to master and try `git merge salty`, then
  `git merge sweet`. What happens? Look at the contents of
  `recipe.txt` - what do the `<<<<<<<`, `=======`, and
  `>>>>>>>` markers mean?
- f\. Resolve the conflict by editing the file to keep the
  content you want, removing the conflict markers, and
  completing the merge with `git add` and `git commit`
  (or `git merge --continue`). Alternatively, try using
  `git mergetool` to resolve the conflict with a graphical or
  terminal-based merge tool.
- g\. Use `git log --graph --oneline` to visualize the merge
  history you just created.
