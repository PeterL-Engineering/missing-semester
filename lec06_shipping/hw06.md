### 1. Inspect a virtual environment

Save your environment with `printenv` to a file, create a venv,
activate it, `printenv` to another file and `diff before.txt
after.txt`. What changed in the environment? Why does the shell
prefer the venv? (Hint: look at `$PATH` before and after
activation.) Run `which deactivate` and reason about what the
`deactivate` bash function is doing.

**A:** The path was changed, 
with the directory to the venv prepended. 
The shell prefers this because it finds Python quickly by checking 
the first path (venv directory).
`deactivate` restores the old path,
clears the cache of executable file paths so `python` doesn't resolve 
to the venv,
and unsets the venv and `deactivate` when the argument isn't nondestructive.
